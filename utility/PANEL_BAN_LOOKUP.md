# Проверка банов в Discord

Сообщения в существующих `bansChannelId` проверяются через панель RNS, без BattleMetrics.

Настройка перед запуском:
- `BAN_LOOKUP_API_URL` в Leaderbot: отдельный адрес API проверки банов, при отсутствии используется `SITE_API_URL`. Внутри Docker: `http://backend:5000`; через публичный nginx: `https://rnserver.ru/api`. Префикс `/api` добавляет nginx, внутренний backend его не требует.
- `LEADERBOT_BAN_LOOKUP_KEY`: одинаковый отдельный случайный секрет в backend и Leaderbot. Он разрешает только чтение этого endpoint. Не использовать ключ выдачи банов.
- Backend предоставляет `GET /api/integrations/leaderbot/bans?q=...` с `Authorization: Bearer ...`.

Сначала развернуть backend, затем настроить секрет и обновить Leaderbot. Без настройки бот явно сообщает о невозможности проверки. Продакшен-настройки этим изменением не изменяются.

Поддерживаются Steam ID, EOS ID, Steam /profiles/ ссылки и поиск по сохранённым никам. Steam /id/ ссылки требуют числового ID. Поиск по нику не удостоверяет личность. Ограничения по нику обозначаются отдельно и не доказывают текущую блокировку аккаунта. Снятые и истёкшие записи исключаются, pending включаются, потому что панель применяет их сразу. Приватные заметки и данные администраторов не выдаются.
